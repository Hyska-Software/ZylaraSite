在代码布局中，智能体可以改动文件并运行程序。Zylara 把边界说清楚：你为每个会话选择一种权限
模式，超出该模式的操作都会变成对话记录中的批准卡片。

## 权限模式

输入框里的权限胶囊可以随时切换模式：

| 模式 | 智能体可以做什么 |
| --- | --- |
| **只读** | 读取文件、查询工作区。不写入，不运行命令。 |
| **审阅** | 提出修改；每一次写入都需要你批准。 |
| **编辑** | 自由编辑文件；运行命令需要批准。 |
| **自主** | 不经询问即可运行命令、编辑、读取密钥文件并操控电脑。会弹出提示 **已启用自主模式**。 |

新代码会话的默认值在 **设置 → 工具 → 代码会话 → 默认权限模式** 中设置。对不熟悉的仓库请选
**只读** 或 **审阅**，把 **自主** 留给那些你愿意让脚本去改的文件夹。

输入框里的 `/permissions` 只是指向那个胶囊，它本身不会切换模式。

计划模式是另一个开关：输入框中的 **计划** 胶囊或 `/plan` 会让智能体在动手之前先提出计划
——参见 [目标与任务](/docs/goals-and-tasks#计划模式)。

## 批准卡片

当某个作超出当前模式时，本轮会暂停，并在对话记录中出现一张卡片：

| 卡片标题 | 触发条件 |
| --- | --- |
| **运行命令？** | 一个未被判定为只读的 shell 命令 |
| **写入改动？** | 创建或编辑文件 |
| **读取文件？** | 读取工作区之外的文件 |
| **读取项目外的文件？** | 路径离开了工作区 |
| **读取密钥文件？** | 匹配密钥特征的文件（`.env`、`*.pem`、`*.key`、凭据） |
| **执行破坏性操作？** | 以破坏性方式删除或覆盖 |
| **访问网络？** | 向白名单之外的主机发起请求 |
| **操控电脑？** | 电脑操作类动作 |

每张卡片提供 **允许**、**拒绝** 和 **始终允许**，授权范围分三级：

- **本会话**——直到会话结束。
- **本工作区**——该文件夹中的所有会话。
- **始终**——本次安装内有效。

你可以填写 **拒绝原因（可选）**；智能体会看到它并据此调整。`Esc` 会拒绝当前挂起的卡片。
有批准挂起时，输入框只提供 **停止**。

## 哪些不需要询问

只读的检查命令在任何模式下都会被识别：`git status`、`git diff`、`git log`、`ls`、`cat`、
`head`、`tail`、`rg`/`grep`、版本探测等。任何组合命令（管道、`;`、重定向）、任何写操作、
任何破坏性操作都不会被判为安全，在 **自主** 之外一定会询问。

智能体同样不能暂存、提交、推送、抓取或拉取——这些是工作台里只有你能执行的操作。参见
[工作台](/docs/code-workbench#提交)。

## 路径与密钥

- 工具被限制在工作区内。要访问工作区之外需要批准，卡片会在你决策前显示路径。
- 即使在工作区内，形似密钥的文件也受保护：`.env`、`*.pem`、`*.key` 和凭据文件。智能体读取
  前会先询问。
- 单次调用写入上限为 2 MB，而且写入必须先读取同一文件，因此智能体无法盲写它从未看过的内容。

## 未信任的工作区

用 **以只读方式打开** 打开文件夹，会为该工作区移除 shell 和编辑工具。页眉保留 **只读**
标记，项目指令也不会加载。在工作区菜单中撤销信任即可回到这一状态。

## Docker 命令沙箱

要给 shell 命令更强的隔离，可在 **设置 → 工具 → 命令沙箱** 中把命令环境切换到 Docker：

| 设置项 | 含义 |
| --- | --- |
| **环境** | **这台电脑**（默认）或 **Docker** |
| **Docker 镜像** | 运行命令所用的镜像；默认 `node:22-bookworm` |
| **容器内网络** | 默认关闭；关闭时命令无法访问网络 |
| **内存（MB）**、**CPU**、**PID** | 资源限制 |
| **只读 rootfs** | 以只读方式挂载容器文件系统 |
| **校验镜像** / **下载镜像** | 使用前检查或拉取镜像 |

只挂载工作区，挂载到 `/workspace`——绝不挂载你的主目录、Docker socket 或凭据。容器以
`--cap-drop ALL`、`no-new-privileges`、非 root 用户、tmpfs 的 `/tmp` 以及上述限制运行。它们
会在退出、超时、取消和关闭标签页时被移除，同一页面的 **清理容器** 可清除遗留实例。

沙箱覆盖 `run_command` 类工具和后台作业。它 **不** 覆盖
[代码执行](/docs/code-execution)，因为后者直接在本机运行 `run_code`。

## 智能体与电脑操作

智能体线程使用同样的模式和批准卡片。智能体自身的权限模式在其编辑器中设置，**电脑操作** 会
额外加上逐操作的批准卡片（截图、点击、输入、按键），除非智能体运行在 **自主** 模式——参见
[电脑操作](/docs/computer-use)。
