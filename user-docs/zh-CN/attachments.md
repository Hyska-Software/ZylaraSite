---
title: 附件
description: 把 PDF、Office、文本、代码和图片文件作为上下文发送，并了解应用从每种文件中提取什么。
---

附件为模型提供可用的材料。Zylara 在后端读取文件，提取其内容，并把该内容作为请求的一部分发送 — 除了你正在使用的提供商，文件本身不会被上传到任何地方。

## 添加文件

- 按输入框中的 **+**，然后选择 **文档**、**图片** 或 **所有文件**。
- 直接把文件或图片粘贴到输入框中。
- 应用提供该选项时，从剪贴板导入。

每个附件都会变成一个带预览和 **移除** 操作的标签。你可以在一条消息中混合多个文件。开关 **设置 → 工具 → 智能体工具 → 将附件发送给模型** 控制附件内容是否被包含在请求中。

## 提取的内容

| 类型 | 提取方式 |
| --- | --- |
| **PDF** | 每页文本（基于文本的 PDF；扫描页没有 OCR） |
| **DOCX** | 从 `word/document.xml` 中提取段落、标题和表格 |
| **PPTX** | 每张幻灯片的文本，包括演讲者备注 |
| **XLSX / ODS** | 每张工作表的单元格值 |
| **CSV / TSV** | 解析后的行，自动检测分隔符 |
| **文本、Markdown、代码、JSON、HTML** | 按文本读取，并检测编码 |
| **图片** | 元数据加上图片本身，在模型支持视觉时原生发送 |

限制：**每个文档 400,000 字符**。更长的文档会被截断，附件也会被标记，以便你知道模型没有看到全部内容。如果细节很重要，请把大文档拆分成多个部分。

## 图片与视觉

图片会原生发送，因此模型必须支持视觉。在 **选择模型** 中使用 **视觉** 筛选来找到这样的模型，否则模型不会收到该图片。支持的格式包括 PNG、JPEG、GIF、WebP、AVIF、BMP 和 ICO；TIFF 会在预览前转换。

## 何时附加而不是粘贴

文件较长、结构化或需要作为文档保留时，请附加；只需要一段文字时，请粘贴。附加的文件会保持被对话引用，因此后续问题可以依赖它们，无需重新上传。

## 文件存储位置

附件会被复制到应用数据文件夹中的 `attachments/`，并在消息负载中通过 id 引用。删除对话会删除它的附件。你想保留在 Zylara 之外的文件应当导出 — 参见[产物](/docs/artifacts)和[资料库](/docs/library)。

## 限制与注意事项

- **没有 OCR**：扫描版 PDF 只能得到很少或没有文本。请先把它转换成文本。
- **没有音频或视频转写**：音频和视频文件作为产物处理，而不是作为附件上下文。
- **结构化提取**：DOCX/PPTX/XLSX 内容按文本和单元格读取；图片、颜色、合并单元格和布局不属于上下文的一部分。
- **提供商限制仍然适用**：非常大的提取内容可能被模型的上下文窗口截断。代码中的上下文计量器和聊天中的错误消息会告诉你何时发生这种情况。
