插件是扩展 Zylara 的包：页面、面板、侧边栏条目、设置标签页、命令、热键、主题、工具、提示词
片段、技能、提供商、模式和智能体模板。插件是可选的，在你安装并启用之前，它们都不会运行。

## 包的内容

`.zplugin` 文件是一个 ZIP，包含 `manifest.json`、可选的 `META-INF/signature.json`，以及插件
需要的文件——界面 HTML、后端 JavaScript、提示词、技能和语言文件。

共有三个层级：

| 层级 | 运行什么 | 何时 |
| --- | --- | --- |
| **声明式** | 什么都不运行：清单只添加条目、命令、设置和主题 | 安装总是安全的 |
| **沙箱** | 界面 HTML/JS 运行在带 `allow-scripts` 的隔离 `zplugin` iframe 中 | 第三方代码的默认层级 |
| **受信任** | JavaScript 在主窗口中运行，通过一条窄桥通信 | 仅在开启 **允许受信任插件**、存在签名并获得你明确同意时 |

签名只能证明 **是谁发布的** 这个包，并不能让代码变安全——安装前请先读权限。

## 安装

1. 在侧边栏打开 **插件**。
2. 使用 **从 URL 安装**（仅限 HTTPS），或选择一个 `.zplugin` 文件；拖放也可以。
3. 按 **检查包**：应用会下载它、验证哈希和签名，并显示它申请的权限。
4. 审阅列表，然后按 **安装**。

像 `zylara://plugin/install?url=…` 这样的深链接会打开同一个审阅步骤。由智能体安装的插件会以
**停用** 状态落地，原因码为 `activation_required`：只有你能启用它。

## 权限

| 范围 | 授予 |
| --- | --- |
| `ui.*` | 页面、面板、插槽、侧边栏条目、设置标签页 |
| `agent.*` | 提示词片段、工具、智能体模板 |
| `providers` | 注册模型提供商 |
| `chat.read` / `chat.write` | 读取对话和添加内容 |
| `commands`、`hotkeys` | 命令面板命令和键盘快捷键 |
| `net:<host>` | 对特定主机的网络访问 |
| `fs.read:<glob>` / `fs.write:<glob>` | 在某个 glob 范围内的文件访问 |

任何超出已授予范围的操作都会以 `PLUGIN_PERMISSION_DENIED` 失败。`process.spawn` 和 `dialog`
属于保留项并被拒绝：插件不能启动进程，也不能打开系统原生对话框。

## 设置

**设置 → 插件**：

| 控件 | 效果 |
| --- | --- |
| **启用插件** | 总开关 |
| **自动更新** | 从已配置的仓库安装更新的版本 |
| **允许受信任插件** | 受信任层级必需 |
| **开发者模式** | 加载本地包并显示额外诊断 |
| **安全模式** | 以所有插件停用的状态启动，且不删除任何东西 |
| **仓库 URL** | 每行一个；本地路径仅在开发者模式下可用 |
| **停用全部插件** | 一次性关闭所有插件 |

如果某个插件让应用无法使用，请以 **安全模式** 启动（或用 `--disable-plugins` 启动应用），
然后移除或更新该插件。你的数据不会被动到。

## 插件商店

仓库是通过 HTTPS 提供的已签名 JSON 文档。应用在解开任何内容 **之前** 会检查仓库密钥、包哈希
和发布者签名，并支持：

- **stable** 和 **beta** 渠道；
- 吊销，可阻止某次更新；
- 更新失败时回滚到上一个版本；
- 多个仓库，用逗号或换行分隔。

v1 的商店没有遥测，也没有支付。

## 更新与移除

- 插件页面里的 **更新** 显示可用版本；**自动更新** 会在新版本出现时安装。
- **卸载** 会移除代码。插件的键值数据、设置和密钥会被保留，除非你选择删除，因此重新安装可以
  恢复之前的状态。
- 如果某次更新破坏了功能，请从插件页面回滚到上一个版本。

## 构建插件

SDK 是另一个话题，但入口是：

- `packages/plugin-sdk` 和 `packages/create-zylara-plugin` 用于搭建骨架；
- `node scripts/plugin/cli.mjs init|build|pack|sign|verify|publish|registry` 用于完整生命周期；
- `pnpm plugin:review <file.zplugin>` 作为审阅关卡；
- 应用内的 `/creator` 模式，会用内置的编写技能构建一个插件，并以停用状态安装。
