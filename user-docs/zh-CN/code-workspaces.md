代码布局把一个对话绑定到你磁盘上的某个文件夹。于是智能体可以读写文件、运行命令、维护计划，
并产出让你在提交前审阅的差异。

## 从一个文件夹开始

第一次切换到 **代码** 时，中间一栏显示 **从一个文件夹开始**：
*"打开一个文件夹，智能体才能在这里读写文件、运行命令。"*

- **打开文件夹…** 打开系统原生文件夹选择器。
- **最近的工作区** 列出你之前用过的文件夹。
- 没有文件夹时，这个布局什么也做不了：代码并不是一个恰好能访问文件的聊天。

Git 仓库和普通文件夹都可以用。在普通文件夹里，更改面板依然工作——它的数据来自智能体的操作
日志——但 **提交** 标签页会显示 **不是 Git 仓库**。

## 信任

在一个文件夹里进行第一轮对话之前，Zylara 会询问 **信任这个文件夹吗？**：

| 选择 | 效果 |
| --- | --- |
| **信任** | 智能体可以读取、编辑并在此文件夹内运行命令。`AGENTS.md`/`CLAUDE.md` 和本地技能会作为项目指令加载。 |
| **以只读方式打开** | 智能体只能读。不能编辑、不能运行命令，项目指令也不会加载。 |
| **取消** | 不打开该工作区 |

未信任的工作区在页眉保留 **只读** 标记，shell 工具保持不可用。之后可以随时在工作区菜单中
撤销信任。

信任之所以重要，是因为文件夹里可能带着指令：`AGENTS.md`、`CLAUDE.md` 和技能文件都会被当作
给智能体的指导来读取。只信任那些你愿意让同事在其中运行命令的文件夹。

## 会话

代码侧边栏列出 **工作区** 及其会话：

| 控件 | 用途 |
| --- | --- |
| **新建会话** | 在选中的工作区里开始一个新对话（`Ctrl/⌘ Shift+A`） |
| **打开文件夹** | 添加另一个工作区 |
| **添加聊天会话** | 把一个已有的聊天对话接入代码布局 |
| **搜索** | 筛选工作区和会话 |
| **插件**、**技能** | 与聊天布局中是同一批页面 |
| 筛选 | **全部**、**含 git**、**不含 git**、**未信任**、**有会话**、**无会话** |
| **无工作区** | 丢失了文件夹的会话 |

每个会话都带有 **自己的模型** 和 **自己的权限模式**，两者都可以在不同轮次之间改变。切换模型
会在对话记录中插入一条分隔线，因此旧回答保留其来源。

### 关联一个聊天对话

**添加聊天会话** 会打开一个对话框：*"选择一个聊天对话，让它在代码布局里也能继续。它在两个
布局中都保持可用。"* 已关联的会话在代码侧边栏标记为 **来自聊天**，而 **从代码中移除**（在
聊天对话菜单中）会解除关联，同时不删除任何内容。

## 会话中智能体能做什么

- 读取文件（分页，带行号），列出目录，按名称或内容搜索。
- 创建文件、替换精确字符串，但要先读取文件。
- 运行命令，运行项目探测到的测试/lint 命令，管理后台作业。
- 读取 Git 状态、差异和日志。
- 维护任务列表，并在计划模式下提出计划。
- 委派给子智能体。

它不能暂存、提交、推送、抓取或拉取：这些是你在工作台里做的操作——参见
[工作台](/docs/code-workbench)。

## 工作区菜单

| 操作 | 结果 |
| --- | --- |
| **打开终端** | 在项目路径打开 shell，不启动会话 |
| **在文件管理器中显示** | 用系统文件浏览器打开该文件夹 |
| **从 Zylara 中移除** | 忘掉该工作区及其会话列表；文件夹不会被删除 |
| **撤销信任** | 让该文件夹在后续轮次中回到只读 |

## 会话按布局分开

代码会话绝不会出现在聊天侧边栏里，聊天对话也不会出现在代码布局中，除非你主动关联。这是有意
的：代码配置会暴露文件与 shell 工具，默默混用两段历史会改变模型能做什么。完整说明见
[对话](/docs/conversations#会话与布局)。
