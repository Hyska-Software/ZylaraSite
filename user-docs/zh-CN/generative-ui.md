title: 生成式界面
description: 智能体可以用原生卡片、表格、图表、时间线和小的交互表单来回答，而不是纯文本。
---

有时最好的回答不是一段话。Zylara 允许模型输出声明式区块，由应用用原生组件渲染：对比表格、
图表、清单、时间线、一组卡片——或者一个替你填好输入框的小表单。

## 工作原理

模型写一个带 `ui` 标签的围栏区块，内容是 JSON。应用按固定契约
（`data/genui-contract.json`）校验该 JSON，只渲染白名单里的组件。区块里没有 HTML、CSS 或
JavaScript，也不会执行任何东西。

JSON 无效时，区块会以代码形式显示，而不是让消息出错。同一套契约在后端和界面中都强制执行，
两边用同一批测试样例校验，因此在一处能渲染的区块在另一处也能渲染。

## 可以渲染什么

| 类别 | 组件 |
| --- | --- |
| 布局 | **card**、**stack**、**grid**、**tabs**、**reveal**、**section**、**divider** |
| 数据 | **table**、**chart**（柱状、折线、饼图）、**stat**、**progress**、**timeline**、**steps**、**checklist**、**keyvalue**、**list** |
| 内容 | **code**、**quote**、**text**、**badge**、**image**、**source**、**link** |
| 交互 | **actions**、**choices** |

典型结果：用表格对比各个方案、用柱状图展示月度数据、用编号步骤描述一次迁移、用时间线讲述
一次故障、用卡片呈现一个决策并附上 **对比场景** 操作。

## 交互是声明式的

有两个组件可以响应点击，但都不会自行发送任何内容：

- **choices**——单选、复选或分段选项，配有提交按钮。提交会用你的选择填好输入框（前面加上
  一句由智能体指定的前缀），你来检查并发送。
- **actions**——最多四个建议的后续步骤。`prompt` 操作会填好输入框；`copy` 操作会把文本复制到
  剪贴板。

渲染出的区块里没有自由文本输入框：输入框始终是你唯一打字的地方。这是有意为之——保持对话
记录可读，也避免出现第二条隐藏的输入路径。

## 限制

| 限制项 | 数值 |
| --- | --- |
| 每个区块的组件数 | 120 |
| 嵌套深度 | 8 层 |
| 每个组件的属性数 | 24 |
| 数组条目（表格行、列表项） | 200 |
| 每个属性的文本长度 | 4,000 字符 |
| 每个区块的源码大小 | 200,000 字符 |
| 每条回答的区块数 | 2 |

设计规则同样会被强制执行：最多四张卡片，图表需要标题和至少两个数据点，表格最多十列，网格
必须由子组件填满。

## 什么时候会用到它

由智能体决定。当你要求对比、仪表盘、计划、清单或一组选项时，它倾向于使用区块——或者当
表格比整段文字更清楚时。想要的话可以直接要求：

> 用表格对比这三个方案，并单独一列说明每档有什么变化。

区块会出现在聊天、代码和智能体的对话记录中。它们属于消息的一部分，因此会随消息一起保存和
导出。

## 安全性

- 只渲染文档化的组件和属性；未知的一律忽略。
- 没有 `eval`，没有内联脚本，没有任意 URL：图片和链接必须是 `http(s)`。
- 区块不能调用工具、修改设置或发起一轮对话。
- 区块内的内容是模型输出，请像对待其他任何回答一样对待它。
