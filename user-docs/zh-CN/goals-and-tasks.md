对真正的任务来说，一条消息往往不够。Zylara 在普通轮次之上增加了四种机制：计划模式、任务
列表、跨轮次延续的目标，以及后台作业。

## 计划模式

打开输入框里的 **计划** 胶囊，或输入 `/plan`（退出时输入 `/plan off`）。智能体会去调研并提出
计划，而不是直接修改文件。

计划卡片会出现在对话记录中，状态有三种之一：**准备中**、**等待批准**、**已批准**。计划就绪
后，你可以选择：

| 操作 | 结果 |
| --- | --- |
| **批准并运行** | 智能体执行该计划 |
| **批准并逐项审阅修改** | 执行时每个文件的写入都需要批准 |
| **继续计划** | 把计划退回修改 |
| **作为目标运行** | 把计划变成带轮次的目标 |

计划模式与权限模式互相独立：它改变的是智能体先做什么，而不是它被允许做什么。参见
[权限与批准](/docs/permissions-and-approvals)。

## 任务

对于包含多个步骤的工作，智能体会维护一份任务列表，显示在 **任务** 卡片里：

- 标题 **任务**，附 *"已完成 N / M"* 和 *"N 项进行中"*；
- 状态 **待处理**、**进行中** 和 **已完成**；
- 列表随步骤完成而更新，因此你能分清是卡住了还是做完了。

输入框里的计划胶囊显示 `N/M` 进度，点击可打开弹层，包含计划状态、任务列表和正在运行的作业。

## 目标

目标是一个跨多个轮次运行的任务，每一轮都是一次完整的对话，拥有自己的工具、批准和产物。

### 开始一个目标

在输入框里输入 `/goal`。它会变成一个可移除的胶囊，下一条消息带上这个请求。智能体自己创建
目标（通过 `goal` 工具），并在对话记录中描述它。

### 轮次

- 目标运行 **1 到 100 轮**；默认值较小，可以调高。
- **自动继续** 会不断开启新轮次，直到目标完成、达到上限或进度停滞。
- 每一轮都是一次普通对话：批准仍然生效，后台会话也可能因为一次批准而暂停。

### 状态

| 状态 | 含义 |
| --- | --- |
| **工作中** | 正在运行某一轮 |
| **自动** | 会自动继续 |
| **手动** | 等你开启下一轮 |
| **已暂停** | 因下列原因之一停止 |
| **已完成** | 完成并被接受 |
| **受阻** | 卡在同一个障碍上 |

暂停原因会明确写出：**由你暂停**、**出错后暂停**、**已达轮次上限**、**连续 3 轮无进展**、
**上一轮被中断**。

### 控件

输入框里的目标胶囊会打开弹层，包含 **本轮后暂停**、**恢复目标**、**延长上限**、
**完成目标**（需确认）、**打开目标** 和 **停用目标**。**目标** 标签页显示任务描述、
**轮次**、**总耗时**、**token**、**费用**、**最近活动**、**复制目标**，以及带每轮状态的
**轮次历史**。

### 提醒卡片

当目标需要你介入时，对话记录中会出现一张卡片：**目标进行中**、**目标已暂停**、**目标受阻**
或 **目标已完成**，并给出原因和相关操作——**恢复目标**、**延长上限**、**完成目标**、
**重新打开目标**、**打开目标** 或 **忽略**。

只有在同一原因重复三次之后，目标才会被标为 **受阻**；卡片会显示 **已记录阻碍（N / 3）**，
让你在那之前介入。

目标运行在应用进程里。关闭 Zylara 会停止这些轮次；云端不会有任何东西继续跑。

## 上下文与缓存

长会话最终会填满上下文窗口。代码页眉里的上下文计量器显示 **已用上下文 N%**，并拆分为
**系统提示词**、**工具定义** 和 **消息**，同时给出输出上限。

- 接近阈值时应用会压缩：较早的消息被摘要，对话记录会标注
  **上下文已压缩 · 已摘要 N 条消息**。
- 阈值可在 **设置 → 通用 → 自动压缩阈值** 中设置（50%–90%，默认 85%）。
- `/compact` 立即压缩。

旁边的缓存胶囊报告 **N% 命中率**，状态包括 **冷**、**预热中**、**稳定**、**缓存已丢弃**、
**未上报** 和 **提供商策略**，并在缓存失效时给出原因（系统提示词变化、工具定义变化、历史
被重写、上下文被压缩、切换模型、TTL 过期）。**缓存诊断** 显示详细信息。

## 后台作业

耗时的命令可以作为作业运行。**后台作业** 弹层列出它们，状态为 **运行中**、**已完成**、
**失败** 或 **已停止**，并提供 **查看作业** 和 **停止作业**。作业会跨过启动它的那一轮，
应用关闭时被终止。

## 子智能体

为了并行调研，智能体可以委派给子智能体。每个子智能体都作为实时行出现在思考区块里，带有状态、
步骤、模型和最近的文本，**打开对话** 会打开只读的对话记录标签页。

- 调研类子智能体（explore、review、general）是只读的：不能编辑、不能用 shell、不能提问、
  不能继续委派；**24 步 / 15 分钟**。
- worker 子智能体可以编辑并运行命令；**48 步 / 30 分钟**，并要求父会话处于 **自主** 模式且
  关闭计划模式。
- 委派深度只有一层，每轮最多四次委派。
